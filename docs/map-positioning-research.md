# Позиционирование на карте: откуда взялись звёзды-якоря и чем их заменить

Заметки по исследованию, 09.09.2026. Всё ниже проверено на живом wplace.live
в одноразовом профиле Chrome (без логина), а не вычитано из минифицированного
исходника.

## 1. История: костыль не изначальный

| коммит | дата | как определялась позиция |
| --- | --- | --- |
| `9e1fc87` Initial | 12.08.2025 | Мировых координат нет вообще. Оверлей — коробка `position: fixed`, `pixelSize = width / rows`. Двигаешь карту — картинка остаётся на месте. |
| `5f8689a` two-point auto adjusting | 11.09.2025 | Появляется `WorldPosition`. Бот создавал **настоящие** избранные места через UI wplace: кликал по пикселю в (−20000,−20000) и (20000,20000), жал «Favorite», ждал появления звезды, читал её `transform`. Отсюда `StarsAreTooCloseError` и `ZoomTooFarError` — две далёкие опорные точки дают заметную погрешность. |
| `a004a60` automatic anchors around images | 23.11.2025 | Звёзды перестают быть настоящими: их подмешивают в ответ `/me`, по две на картинку (±1000 px), прячут через CSS, для каждой позиции берут ближайшую пару. Это и есть текущий код в `world-position.ts`. |

Причина у всех трёх поколений одна: **wplace не отдаёт наружу преобразование
мир↔экран, а маркеры-звёзды — единственные DOM-элементы, которые сайт сам
позиционирует по произвольным lat/lng.** Каждое поколение чинило побочный вред
предыдущего: сперва засорение реального избранного пользователя, потом потерю
точности от двух далеко разнесённых якорей.

К обходу анти-бота звёзды отношения не имеют.

## 2. Экземпляр карты достижим, и настоящий трансформ тоже

wplace рисует через MapLibre GL. Экземпляр не выставлен в `window`, но его
держит собственный стор состояния wplace, а стор — обычный экспорт чанка
SvelteKit:

```js
// чанк, в котором лежит и анти-бот-код; сейчас Dckshkh0.js
const store = (await import(chunkUrl)).dt
store.map              // живой maplibre Map — тот же объект, что использует сайт
store.automatedClicks  // false
```

Находится за **1 мс** на холодной загрузке (чанк уже выполнен, поэтому
`import()` отдаёт его из реестра модулей), `store.map` к этому моменту уже
проставлен. Патчить `Map.prototype` не нужно — это чтение.

Как найти без захардкоженного хэша в имени чанка: пройтись по
`performance.getEntriesByType('resource')` в поисках `_app/immutable/**.js`,
сделать `import()` каждого и взять тот объект-экспорт, у которого есть и `map`,
и `automatedClicks`. Импорт безвреден: приложение эти чанки уже выполнило.

Запасной путь, если форма стора изменится: на document-start повесить хук на
`HTMLCanvasElement.prototype.getContext` и при запросе `webgl2` на
`canvas.maplibregl-canvas` прочитать `new Error().stack`. Стек называет чанк
maplibre (`at to._setupPainter (…/auT6d-NR.js…)`), тот экспортирует весь
неймспейс maplibre через ленивую CJS-обёртку; дальше патчим
`Map.prototype._render` и ловим `this` на следующем кадре. Замер: прототип
пропатчен на 254 мс, экземпляр пойман на 1132 мс, без единого действия
пользователя. Имена свойств переживают минификацию, потому что этот чанк —
готовый dist самого maplibre, завёрнутый в CJS.

### Точность, по замерам

1. **Формулы проекции в `world-position.ts` бит-в-бит совпадают с MapLibre.**
   `longitudeToWorld`/`latitudeToWorld` против
   `MercatorCoordinate.fromLngLat().x * 2048000`:
   `1037359.25108485` против `1037359.25108485`.
2. **Для размера пикселя достаточно зума.** Измерено через `project()` по двум
   точкам: `6.433607412283278` (X) и `6.433607412276229` (Y); формула
   `512 * 2 ** zoom / 2048000` даёт `6.4336074122716616`.
3. **Сквозная проверка.** Спроецировал центр выбранного мирового пикселя в
   `(834.52, 320.02)`, отправил туда клик — wplace запросил
   `GET /s0/pixel/1037/704?x=377&y=572`, ровно тот пиксель, который задумывался.

### Что это заменяет

Под снос: `FAVORITE_LOCATIONS`, `FAVORITE_LOCATIONS_POSITIONS`,
`addFavoriteLocation` и его вызовы (`bot.ts:128-154`, `bot.ts:730`); патч `/me`
(`favoriteLocations.unshift(...)`, `maxFavoriteLocations = Infinity`,
`bot.ts:1039-1040`); `extractScreenPositionFromStar` с его `slice(32, -31)`;
`$stars`, `updateStars`, `findAnchorsForScreen`, `updateAnchor`,
`anchor1Index`/`anchor2Index`; правило
`:nth-child(-n + FAKE_FAVORITE_LOCATIONS of …)` в `style.css` и его подстановка
в рантайме.

| сейчас | вместо |
| --- | --- |
| `toScreenPosition()` по двум звёздам | `map.project([lng, lat])` (плюс offset прямоугольника канваса; сегодня он `0,0` на весь экран) |
| `fromScreenPosition()` | `map.unproject([x, y])` |
| `pixelSize` по разности звёзд | `512 * 2 ** map.getZoom() / 2048000` |
| `moveMap()` синтетическим драгом (`bot.ts:847`) | `map.panBy` / `map.jumpTo` |
| `zoomIn()` циклом колёсика (`bot.ts:988`) | `map.zoomTo(Math.log2(pixelSize * 2048000 / 512))` |
| MutationObserver на `.maplibregl-canvas-container` (`bot.ts:180-200`) | `map.on('move')` / `map.on('render')` |

`project()` вдобавок корректен при повороте и наклоне карты; звёздная
математика берёт `pixelSize` только из разности по X и поедет при
`bearing != 0`. `dragRotate` сейчас выключен, но `touchZoomRotate` включён.

## 3. Анти-бот: что там на самом деле

Прокрался по всему графу модулей — 269 чанков.

- **BotD** (открытый детектор ботов от FingerprintJS) — ищет артефакты
  автоматизации: `webdriver`, `cdc_`, selenium, phantom, electron,
  headless_chrome. Юзерскрипт в обычном Chrome под это не подходит.
- **pawtect** — WASM (`pawtect_wasm_bg.*.wasm`), подписывает защищённые запросы
  заголовком `x-pawtect-token`.
- **Turnstile** плюс сигнал Cloudflare `cf_likely_automated`.

Что скармливают в WASM перед подписью:

```js
Pu(q.data.id)               // user id
Au(q.data.discordId ?? ``)  // discord id
Ru(navigator.webdriver)     // set_automated_browser
Iu(F.automatedClicks)       // set_automated_clicks
r.bot && Mu(r.botKind)      // вердикт BotD
Nu(e)                       // request url
```

`automatedClicks` — **залипающий** флаг. Вот все три места во всём приложении,
где он выставляется (`Cox-7aWj.js`, компонент режима рисования):

```js
y.map.on(`click`,       e => { e.originalEvent.isTrusted || (oe.automatedClicks = !0); … })
y.map.on(`touchstart`,  e => { e.originalEvent.isTrusted || (oe.automatedClicks = !0); … })
y.map.on(`pointerdown`, e => { e.originalEvent.isTrusted || (oe.automatedClicks = !0)     })
```

Во всём приложении ровно **три** вхождения `isTrusted`, все три — здесь.
`mousemove` и `keypress` слушаются рядом же и не проверяются. То есть нынешняя
постановка пикселя «`mousemove` + пробел» (`bot.ts:386-413`) стоит точно по
безопасную сторону проверки — по замыслу, а не по везению.

Флаг живёт в памяти вкладки и не пишется в localStorage, так что перезагрузка
его сбрасывает. Помнит ли его сервер, с клиента не видно.

## 4. Опаснее ли прямые вызовы камеры? Нет, безопаснее

Повесил на живую карту те же слушатели, что вешает wplace, и прогнал четыре
сценария:

| сценарий | какие события карты сработали |
| --- | --- |
| **A.** текущий `moveMap()` — синтетические `mousedown`/`mousemove`/`mouseup` | `mousedown(isTrusted=false)`, `mouseup(false)` |
| **B.** `map.panBy([30,30], {duration:0})` | `move`, `moveend` — **ни одного input-события** |
| **C.** текущий `zoomIn()` через `WheelEvent` | `move`, `zoom` |
| **D.** текущая постановка пикселя (`mousemove` + пробел) | ничего |

Ни один сценарий сегодня не выставляет `automatedClicks` — ни `click`, ни
`pointerdown`, ни `touchstart` нигде не возникают. Но:

- **A уже сейчас отдаёт в MapLibre два события с `isTrusted: false`.** Проверки
  на них нет, но она в одну строку от трёх существующих. Это единственное место,
  где бот кладёт недоверенные события прямо на карту.
- **B не отдаёт ничего.** Переход на `map.panBy` / `jumpTo` / `zoomTo` эти два
  события убирает. Это не новый риск, а снятие имеющегося.

### Правила, которые нельзя нарушать при переделке

1. Никогда не отправлять `click`, `pointerdown` и `touchstart` на канвас карты.
   `.click()` по собственным кнопкам wplace (палитра, «Paint») безопасен —
   `map.on('click')` на них не срабатывает.
2. Оставить постановку пикселя на `mousemove` + пробел. Замена на клик по карте —
   это ровно тот путь, который флагается.
3. Импортировать анти-бот-чанк ради чтения стора безвредно: он уже выполнен,
   `import()` переиспользует модуль и никаких побочных эффектов не запускает.

`store.automatedClicks` доступен на чтение, так что виджет может показывать,
засветилась сессия или нет.
